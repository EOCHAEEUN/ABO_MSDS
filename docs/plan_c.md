## 0. 무엇을 확인하려는가

**질문:** 개발 판단에 쓰지 않은 새 MSDS 문서에서, 실제 문서를 보강해 학습한 QLoRA가 Base zero-shot · Base few-shot보다 핵심 필드 추출 정확도가 나은가.

- C는 **개선 가능성을 높이고, 개선됐을 때 믿을 근거를 만드는 계획**이다. 우위를 보장하지 않는다.
- **QLoRA는 적은 메모리로 미세조정하는 방법이지 few-shot보다 정확해지는 것을 보장하는 방법이 아니다. 입증 대상은 "이 과제에서 학습한 모델의 효과"다.**
- 결과가 어느 쪽이든 보고한다(9절에 결론 문구를 미리 정해 둔다).

## 2. 3일판과의 관계 — **결정: 3일판 결론을 C 결과까지 보류**

- 모델 고정 · 최종 비교표 · 성과 판정(plan.md 9절)은 **새 test(`test2`) 결과로 한다.** 3일판 일정의 "3일차 Real Test 최초 평가"는 C 최종 평가로 옮긴다.
- **기존 test 20건은 C의 보조 평가로만 쓴다.** 봉인은 그대로 유지하고(어떤 모델도 돌리지 않음), C 최종 모델 고정 후 test2와 **같은 시점에 조건별 1회** 평가한다. 노출 이력을 밝히고 **test2와 합산하지 않는다.**
- 추출 파이프라인 · 채점기 · API · DB · 검토 화면은 C와 무관하게 계속 진행한다. 화면 시연에는 현재 후보인 r1을 쓰되 "최종 모델"로 표기하지 않는다.

## 4. 분할 규칙 (라벨링 전에 확정)

기존 `data/splits.csv` 규칙을 확장한다. `scripts/check_splits.py`에 검사를 추가한다.

1. **제조사 · 제품군 · 개정판 · 번역본**이 분할 사이에 겹치지 않는다(`split_group`).
2. **test2의 제조사는 기존 어느 분할(train · val · test · val_en)에도 없는 제조사**로 한다. 기존 test는 노출 이력이 있으므로 그 제조사도 피한다. 예외 없음(09-27: KR-HENKEL-001은 같은 회사 EN-HENKEL-001의 EC 정보가 증강 판단에 쓰여 `excluded`).
   이미 개발에 쓰인 문서(정답 폴더 · few-shot · 학습 JSONL · 모델 출력에 이름이 있는 문서)는 split을 바꿔도 test2에 넣지 않는다. 검사기가 오류로 잡는다.
   **적격성:** 원문을 판독해 정답을 확정할 수 있는 문서는 평가 대상이다. 원문의 빈칸은 스키마대로 라벨링하고, 전처리 · 텍스트 추출 실패는 평가 분모에 남긴다. 원본 손상 · 필요한 페이지 누락으로 정답을 확정할 수 없는 문서와 범위 밖 문서(다중 SDS 묶음 · 영문 외 외국어)는 분할 확정 전에 `excluded`로 두고 사유와 건수를 기록한다.
3. 분할은 **라벨링과 모델 추론 전에** 문서 목록만 보고 정한다. test2 문서는 분할 직후 봉인 대상에 넣는다.
4. split 이름: `train`(기존+추가), `val`(기존+추가), **`test2`**(새 test, 정답 `eval/test2/`), 기존 test는 `test`(노출 이력 표기) 유지.
5. **신규 배정 규칙 — 결정적 균형 배정** *(09-27 결정권자 승인. **다음 수집분부터** 적용한다 — 두 번째 수집분 17건은 라벨링 전에 기록된 제안 배정을 기준으로 중복 · 적격성 · 그룹 충돌 · 노출만 바로잡는다. 도구 `scripts/propose_splits.py`)*
   - **입력:** 사전 메타데이터(doc_id · lang · form · manufacturer · split_group)만. 정답 · 모델 성능 · `sources.csv`의 집계 열(성분 수 · 신호어 등)은 보지 않는다. 결과를 보고 재배정하지 않는다.
   - **기존 배정 유지:** `splits.csv`에 있는 문서는 옮기지 않는다. 이미 있는 `split_group`의 신규 문서는 그 그룹을 따른다(국문 train · val · test2 그룹 → 같은 분할, 그 그룹의 영문판 → train · val이면 val_en, test2면 excluded 권고). 기존 test 그룹의 국문 문서는 excluded 권고(test 동결, 다른 분할은 제조사 규칙 위반), 영문판은 사람 판단.
   - **그룹:** 사람이 정한 `split_group` 값을 그대로 쓴다(같은 제조사의 다른 제품, 번역 · 개정 문서를 묶음). 제조사명 · 제품명을 이어 붙여 키를 만들지 않는다. 다른 그룹인데 제조사 표기가 같으면 제안표에 "split_group 확인"을 띄운다.
   - **신규 그룹:** 영문만 있으면 val_en, 영문 외 외국어는 excluded. 국문이 있으면 아래 균형 배정.
   - **순서:** `sha256(JSON 배열 [SEED, split_group])` 오름차순. SEED = `C-2026-09-27` 고정. 바꾸려면 이유를 `report/decisions.md`에 먼저 적는다. **원하는 구성이 나올 때까지 SEED를 바꾸지 않는다.**
   - **목표(칸):** train 50 · val 15 · test2 현행 30 · test2 수입품 국문판 10(3절). 칸마다 부족분 = 목표 − 현재 건수(기존 + 이번 제안에서 앞서 배정된 것), 부족분 비율 = 부족분 ÷ 목표(분수로 정확히 비교). test2 현재 건수는 역할 `main`과 점검 결과가 나올 때까지 자리를 차지하는 `pending`만 센다(`exposed` · `oldform`은 세지 않음). 노출 · 점검 대기 문서가 있는 test2 그룹을 따르는 신규 문서는 세지 않고 "영향받은 그룹"으로 표시한다.
   - **들어갈 수 있는 분할:** train은 같은 제조사가 val · test · test2에 없을 때, val은 train · test2에 없을 때, test2는 같은 제조사가 다른 어느 분할에도 없고 그룹 문서에 개발 노출 이력(`check_splits.py`의 노출 검사)이 없을 때. 구서식만 있는 그룹은 test2 목표가 없어 train · val 중에서 고른다.
   - **선택:** 부족분이 1 이상인 분할 중 ① 그룹 국문 문서 수가 남은 부족분 안에 들어가는 곳 ② 부족분 비율이 큰 곳 ③ 동률이면 test2 > val > train(train은 기존 train 제조사의 다른 제품으로도 채울 수 있어서). 들어가는 곳이 없으면 비율이 가장 큰 곳에 두고 "목표 초과"를 표시한다. 부족분이 남은 분할이 없으면 "사람 판단".
   - **서식이 섞인 그룹:** test2 비율은 그룹의 주 서식(국문 문서가 가장 많은 서식, 동수면 현행 > 수입품 국문판) 칸으로 보고, 들어가는지는 서식별로 본다. 제안표에 "서식 혼합 그룹"을 표시한다. test2에 간 구서식 문서는 따로 보고한다.
   - **사람 확인:** 제안표에서 적격성(스캔 · 판독 불가 · 범위 밖) · 중복 · 규칙 위반을 확인한 뒤 `splits.csv`에 옮기고 `check_splits.py`로 검사한다. 확인에서 빠진 문서는 excluded(사유 기록)로 두고 다시 돌린다. 이때도 SEED는 바꾸지 않는다.

## 6. 평가 설계 (학습 전에 고정)

**비교군 4개** — 같은 평가 문서, 같은 런타임(Transformers 4bit NF4, greedy, thinking 끔):

| 조건 | 설명 |
|---|---|
| base_zs | 출발선 |
| base_fs | few-shot. **예시는 지금 그대로(KR-HANIL-002 + KR-KUMHO-002)** — 둘 다 수기 검증 완료, train 문서, 평가 전에 고정 |
| qlora_r1 | 기존 r1 그대로(`runs/0926_r1`). **보강 전 대비 실제로 나아졌는지** 보는 기준 |
| qlora_final | 보강 데이터로 Base에서 새로 학습한 C1(`qlora_c1`) · C2(`qlora_c2`) 중 새 val로 채택한 모델 |

**지표:**
- **주지표: 문서 완전 정답률 — 확장 기준**(`doc_exact_ext_rate`: 기존 기준 + `nocas` 정답 + 다른 칸 오입력 없음). 기존 기준 정답률(`doc_exact_rate`)도 함께 보고한다.
- 필드별: 파싱률 · 스키마 준수율 · 제품명 · 신호어 · GHS F1 · H코드 F1 · CAS F1 · pair F1 · `nocas` F1 · 무근거 생성 · 다른 칸 오입력.
- **악화 불허 필드:** 파싱률 · 스키마 준수율 · 제품명 · CAS F1 · pair F1 중 하나라도 base_fs보다 떨어지면 "우위" 결론을 내지 않는다.
- **문서 단위 짝 비교:** 조건 쌍마다 승 · 패 · 무 수와 부트스트랩 신뢰구간을 함께 보고한다. 부트스트랩은 **split_group 단위**로 복원추출한다(같은 제조사 문서는 함께 뽑음). 부호 검정은 참고용이다.
- 서식별(현행 · 구서식 · 수입품) 분리 보고, 합산 금지(기존 원칙). test2와 기존 test도 합산하지 않는다.
- **test2 역할 목록(09-27):** `eval/test2_roles.csv`로 test2를 주 분석 대상(`main`) · 구서식(`oldform`) · 노출 보조평가(`exposed`)로 나눈다. 채점 · 짝 비교가 같은 목록을 쓰고 목록의 모든 문서를 분모에 둔다. test2에는 "전체" 합산을 두지 않는다. 점검 대기(`pending`)가 남으면 실험을 고정하지 않는다. 고정 때 분석 대상 목록(doc_id · 역할 · 언어 · 서식 · 그룹)을 기록하고, 고정 뒤 바뀌면 출력 생성 · 채점을 거부한다(채점기 변경 꼬리표로 허용하지 않음. 대상을 바꾼 분석은 결정 기록 후 별도 사후 분석). 역할은 정답 · 모델 결과를 보고 바꾸지 않는다.

**채점기 동결:** 평가 전에 `eval/score.py`를 고정하고 커밋 해시를 기록한다. 회귀 테스트(`test/test_score.py`, 현재 9건)가 통과해야 한다 — pair만 틀린 경우, `nocas`만 틀린 경우, 영업비밀 플래그, 다른 칸 오입력, 무근거 생성, 줄이 갈린 CAS, 빈 예측.

## 7. 학습 예산과 선택 규칙

- **학습 횟수 상한: 2회.**
  - **C1:** 보강 데이터만 바꾼다. 설정은 r1과 같고(epoch 2 · 배치 1×8 · lr 2e-4), step 수는 데이터 양에 따라 늘어난다. → 개선이 나오면 "데이터 보강 + 그에 따른 학습량 증가"의 효과로 보고한다(둘을 분리했다고 주장하지 않는다).
  - **C2 (선택):** C1에서 한 가지만 바꾼다. 무엇을 바꿀지는 C1 결과를 보고 새 val로 정한다.
- Base에서 새 어댑터로 시작한다. r1은 보존한다.
- **조건 선택은 새 val(기존 6 + 추가분)로만 한다.** val 오류를 보고 val 문서의 표기를 흉내 낸 데이터를 만들지 않는다.
- **채택 기준:** 새 val에서 qlora_r1 대비 악화 필드가 없고, 1절의 목표 오류(EC→KE · 짧은 제품 코드 · 함유량 칸 CAS · JSON 깨짐)가 실제로 줄어야 한다.
- **중단 기준:** C1이 새 val에서 목표 오류를 줄이지 못하면 C2 없이 멈추고 "데이터 보강 효과 미확인"으로 보고한다.
- **test2와 기존 test는 모델을 고정한 뒤 조건별 1회.** `eval/seal.py`로 봉인하고 태그를 남긴다.

## 9. 결론 문구 (결과 보기 전에 정해 둔다)

test2 결과는 **주 분석 대상(`eval/test2_roles.csv`의 `main`)** 기준이다. test2의 구서식 · 노출 보조평가 문서는 따로 보고하고 결론에 넣지 않는다(3 · 6절). "개발에 쓰지 않은 새 문서"라는 표현은 `main`에만 쓴다.

| test2 결과 | 결론 |
|---|---|
| qlora_final − base_fs 주지표 차이의 신뢰구간 하한 > 0 + 악화 필드 없음 | "개발에 쓰지 않은 새 문서에서 학습의 이점이 확인됐다" (문서 수 · 그룹 수 · 신뢰구간 함께) |
| 신뢰구간이 0을 포함 | "few-shot과의 정확도 차이를 확인하지 못했다" — **동등하다는 뜻이 아니다.** 입력 토큰 비율은 test2에서 다시 잰 값으로 함께 보고 |
| 신뢰구간 상한 < 0 | "few-shot보다 정확도가 낮다" + 떨어진 필드, 입력 토큰 절감과의 교환 관계 |
| qlora_final − qlora_r1 신뢰구간이 0을 포함하거나 음수 | "데이터 보강 효과를 확인하지 못했다" |

신뢰구간은 제조사 그룹 단위 부트스트랩이다. 그룹이 적으면 구간 추정 자체가 불안정하므로 문서 수와 그룹 수를 함께 적는다. (09-27 수정: "차이가 신뢰구간 안" → "신뢰구간이 0을 포함", "입력 토큰 약 45%"는 val 수치라 test2에서 다시 측정)

## 10. 기존 자료의 처리

- **기존 test 20건:** 2절대로 보조 평가. 노출 이력(EC 증강 판단에 텍스트 참고, 정답 열람)을 밝힌다. EC 문서 2건(KR-BARTOLINE-001, EN-HENKEL-001) 제외 전후 비교는 **결과가 그 문서에 얼마나 기대는지 보는 보조 분석**일 뿐, 독립성을 되돌리지 않는다.
- **기존 val 6건:** 새 val에 포함. 오류 분석에 계속 쓰되 조건 선택을 이 6건에만 의존하지 않는다.
- **val 형식 변형(`val_var`):** 같은 문서의 표기 변형이라 독립 표본이 아니다. 안정성 참고로만.
- **제조사 교차검증(`qlora_cv_r1`, 2 fold):** 분석 자료. few-shot 예시가 평가 제조사와 겹쳐 비대칭이었다.
