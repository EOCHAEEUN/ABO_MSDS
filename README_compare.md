# 라벨 대조 도구

두 라벨 뭉치를 맞춰본다. 쓰임이 둘인데 하는 일은 같다.

| 쓰임 | A | B |
|---|---|---|
| 모델 채점 | 골든셋(사람) | 모델 출력 JSONL |
| 이중 라벨링 일치율 | 강덕우 시트 | 김건하 시트 |

## 넣을 파일

**사람 라벨** — 구글 시트에서 `파일 → 다운로드 → CSV`로 시트마다 한 장씩.
라벨링 시트와 성분표 시트를 쉼표로 이어서 넘긴다.

**모델 출력** — 한 줄에 문서 하나인 JSONL.

```json
{"doc_id":"KO-001","제품명":"...","신호어":"경고",
 "GHS분류":["..."],"유해위험문구":["H319 ..."],
 "성분":[{"성분명":"물","CAS":"7732-18-5","KE":"자료없음","함유량":"25~35"}]}
```

키 이름은 한글/영문 어느 쪽이든 받는다(`doc_id`/`문서ID`, `components`/`성분` …).
JSON 파싱에 실패한 줄은 건너뛰고 줄 번호를 경고로 찍는다 — 파싱률을 따로 세려면 그 숫자를 쓴다.

## 실행

```bash
# 모델 채점
python scripts/compare.py \
  --a data/golden_main.csv,data/golden_comp.csv \
  --b runs/qlora_out.jsonl \
  --name-a 골든 --name-b QLoRA \
  --out reports/qlora

# 이중 라벨링 대조
python scripts/compare.py \
  --a sheets/라벨링_강덕우.csv,sheets/성분표_강덕우.csv \
  --b sheets/라벨링_김건하.csv,sheets/성분표_김건하.csv \
  --name-a 강덕우 --name-b 김건하 \
  --out reports/interlabeler
```

## 나오는 것

화면에 항목별 지표가 뜬다. 단일값(제품명·신호어)은 일치율, 여러 값이 나오는 항목
(GHS분류·유해위험문구·성분)은 정밀도·재현율·F1이다. **누락과 과생성을 따로 센다** —
둘을 합치면 "못 뽑는 모델"과 "지어내는 모델"이 같은 점수로 보인다.

`reports/.../review.csv` 에는 **어긋난 항목만** 담긴다. 눈으로 볼 건 이 파일뿐이다.

| 구분 | 뜻 |
|---|---|
| 불일치 | 양쪽 다 값이 있는데 다르다 |
| B에 없음 | A에만 있다 (모델 채점이면 누락) |
| A에 없음 | B에만 있다 (모델 채점이면 과생성) |
| 체크디짓 오류 | CAS 형식은 맞는데 검증에 실패 — 오타 의심 |
| 미판정 | 값이 `-`나 빈칸이라 자료없음/해당없음 판정 불가 |

## 무엇을 같게 보고 무엇을 다르게 보나

비교는 `scripts/compare_norm.py`의 **느슨한 키**로 하고(채점기용 `core/normalize.py`와는 별개), 리포트에는 **원문 값**을 보여준다.
그래야 "왜 달랐는지"를 원문과 대조할 수 있다.

같게 본다 — 공백, 콜론·세미콜론, 구분자 하이픈, 불릿, 끝 마침표, 물결표 변형
(`∼` `～` `-` → `~`), 함유량의 `이상`·`미만`·`%`, CAS에 붙은 `/ KE-xxxxx`, KE의 괄호.

다르게 본다 — `자료없음`과 `해당없음`(고시 제11조제7항에서 뜻이 갈린다),
같은 분류의 다른 표현(`심한 눈 손상성/눈 자극성` ↔ `심한 눈 손상 또는 자극성물질`).
뒤엣것을 자동으로 붙이려면 동의어 표가 필요한데, 그건 사람이 판정해 쌓아야 한다.
지금은 검토 목록에 올려서 눈에 띄게 한다.
